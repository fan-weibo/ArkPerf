- 设备：emulator 6.1.0.126(SP1DEVC00E120R4P11) / API 24（模拟器常驻，两轮测量间未重启）
- 基线测量：2026-09-21 23:05~23:32（build #1，含坏味道）

- 口径：同设备、同参数、同采样数；冷启动带锚点归一化 + Mann-Whitney 检验

## 六、过程中发现并修复的工具缺陷（诚实记录）

1. **冷启动 compare 测错对象（严重，已修）**：`compare` 不传包名时回退默认包名（系统设置），
   导致首轮"优化后"测量实际测的是锚点应用，产出 -32.66% 的假阳性。
   修复三道防线：① 不传包名时从基线 JSON 恢复测量对象；② 当前对象与基线不一致直接拒绝执行（口径断裂 fail-fast）；
   ③ 目标=锚点时打印醒目警告。修复后复测得到真实结论（-68.2%）。
2. **内存判定器盲区：有界缓存填充期误判泄漏（已修）**：优化后首轮测量 2082 kB/min 踩线判 🔴——
   4MB 有界缓存的填充爬升被计入全程斜率。为 `judge_staircase` 增加 **capped（有界增长）形态识别**：
   leak 判定后检查后一半回落点是否饱和（速率 <512 kB/min 或单调性 <0.7），饱和则改判 🟡 有界增长。
   验证 6/6：基线序列仍判 🔴 阶梯（39956 不变）、优化序列判 🟡/✅、全程单调泄漏不误判 capped。
   复测（预热周期完成填充后）三维度全 ✅ 锯齿。

## 七、结论

自研示例应用 PerfLab 的三类注入坏味道均被工具有效检出（baseline 全中，泄漏速率误差 <0.2%），
五处优化修复后三项指标全部显著改善并判定翻转，且改善幅度远超统计噪声下限（冷启动 4.3×MDD、
内存 -99.8%、卡顿 -100%）。优化前后对比闭环（赛题第 5 条）成立。
