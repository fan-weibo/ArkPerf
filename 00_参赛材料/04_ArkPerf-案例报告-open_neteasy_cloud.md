# open_neteasy_cloud 优化前后对比报告（真实开源应用案例）

- 被测应用：`com.example.neteasy_cloud` / EntryAbility（仿网易云音乐开源 ArkTS 项目）
- 测量场景：`--scene discover` 场景直达 IndexPage"发现"Tab（自建 scene 路由，见方法学）
- 设备：emulator 6.1.0.126(SP1DEVC00E120R4P11) / API 24（模拟器常驻，未重启）
- 基线：2026-09-22 13:21 安装（Build A，原图直链）
- 优化：2026-09-22 18:01 安装（Build B，14 处网络图加 CDN 尺寸参数）
- 口径：每轮测量前 `bm clean -n <bundle> -c` 清 Image 磁盘缓存（统一冷缓存，见方法学）

## 一、优化内容

"发现"页 14 处网络图片全部使用**原图直链**（网易 CDN），改为按显示尺寸请求缩略图（`?param=WxH`，网易云 CDN 官方缩放参数）：

| 位置 | 显示尺寸 | 数量 | 请求尺寸 | 原图实测 |
|---|---|---|---|---|
| 我的-歌单封面 | 56×56 | 1 | 200y200 | 153KB |
| Swiper banner | 349×145 | 3 | 700y290 | 1080×420 / 31KB |
| 推荐歌单封面 | 107 宽 | 6 | 400y400 | 最大 1024×1024 / 88KB |
| 新碟封面 | 107 宽 | 3 | 400y400 | **36771×27002 / 17.9MB**、4000×4000 / 3.4MB 等 |
| MV 封面 | 337×213 | 1 | 800y800 | 800×800 / 62KB |

下载量实测（8 个唯一 URL，主机侧）：**21.9MB → 518KB（-97.6%）**。
其中"新碟"第一张原图为 36771×27002 像素的 17.9MB 巨图，属典型的"未按显示尺寸请求"性能事故。

## 二、总体结果

| 维度 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| 加载期 CPU 占用（中位） | 11.88% 🟡 轻度 | 1.02% ✅ 低 | **-91.4%，判定翻转** |
| 内存稳态 PSS | 156.8 MB | 56.6 MB | **-63.9%（-100.2 MB）** |
| 下载量（8 个唯一 URL） | 21.9 MB | 518 KB | **-97.6%** |
| 主线程卡顿 | 0 次 ✅ | 0 次 ✅ | 不变（健康本底） |

## 三、分项说明

### 3.1 加载期 CPU（冷缓存，discover 场景启动后 10s 窗口）

- 基线：中位 11.88%，峰值 12.84%（序列 12.84 / 11.88 / 10.83）——下载+解码 21.9MB 的持续成本；
  对照该应用空闲本底 0~0.95%，此为纯图片加载开销
- 优化后：中位 1.02%，峰值 1.21%（序列 0.00 / 1.21 / 1.02）——518KB 数秒内完成，回落到空闲水平

### 3.2 内存稳态 PSS（加载完成后的周期回落点）

- 基线：156.8MB（原图解码位图常驻：如 4000×4000 解码位图 64MB）
- 优化后：56.6MB（400×400 解码位图 0.64MB）
- 降幅 -100.2MB；三维判定均为 ✅ 锯齿（基线同为 ✅，无泄漏，差异在绝对占用）
- 证实 Image 组件对网络图**按原图尺寸解码并常驻内存缓存**——按显示尺寸请求是有效的内存优化手段

### 3.3 主线程卡顿

两轮均 0 次系统卡顿判定（10 次注入滑动）。该应用本底健康，优化收益不体现在卡顿维度，如实记录。

### 3.4 弱网场景的额外收益（未测量，定性说明）

下载量 -97.6% 在弱网环境直接转化为首屏图片出现时间的大幅缩短；本模拟器网络过快，此项未纳入量化对比。

## 四、方法学记录

1. **Image 磁盘缓存会掩盖图片加载成本**：首次内存测量全平稳（PSS 恒 156.8MB），截图发现图片早已
   缓存命中。修正为每轮测量前 `bm clean -c` 清缓存，冷缓存口径下才测得到加载期 CPU 成本。
2. **两版缓存口径公平性**：优化版更换 URL（缓存键含 query）天然冷缓存，基线侧清缓存后两边口径一致。
3. **scene 路由为测量基建**（Build A 与 Build B 均含，非优化变量）：EntryAbility 读
   `want.parameters.scene` → 直达 IndexPage 并默认选中"发现"Tab，全程无人工 UI 导航。
4. **CPU 差异为加载窗口中位数**，样本 3 次、两轮同口径；内存为 5 周期回落点稳态（强制 GC 已启用）。

## 五、结论

在真实开源应用上验证了"图片未按显示尺寸请求"这一典型体验问题的检测与优化闭环：
工具定位到加载期 CPU 11.88%（对照空闲本底 0.95%）与内存稳态 156.8MB，
通过 14 处 CDN 尺寸参数改动，CPU 回落到 1.02%（-91.4%）、内存降至 56.6MB（-100.2MB）、
下载量减少 97.6%，卡顿维持健康本底。与 PerfLab（注入坏味道的可控验证）互补，
本案例证明了工具在真实代码库上的检测与优化指导能力。
